## `.github/workflows/ci.yml` – first-stage CI

**Purpose:**
This workflow runs the actual tests and build steps, produces JUnit XML test reports and uploads them as an artefact. **It creates no CheckRuns**, so that it also works for PRs from forks. The test reports are published by the second workflow.

## ASCII flow diagram

Here is an ASCII flow diagram that visualises the two workflows and their dependencies:

```sh
                       ┌─────────────────────┐
                       │     GitHub Push      │
                       │   or Pull Request   │
                       └─────────┬──────────┘
                                 │
                                 ▼
                       ┌─────────────────────┐
                       │      CI Workflow    │
                       │  (.github/workflows/│
                       │        ci.yml)      │
                       └─────────┬──────────┘
                                 │
          ┌──────────────────────┼───────────────────────┐
          │                      │                       │
          ▼                      ▼                       ▼
┌─────────────────┐     ┌─────────────────┐     ┌───────────────────┐
│ Node.js/TS Steps│     │ Lua Steps        │     │ Build Client      │
│ - checkout      │     │ - create output  │     │ - npm run build   │
│ - cache modules │     │   dir            │     │ - upload artifacts│
│ - npm ci        │     │ - run Busted     │     └───────────────────┘
│ - lint          │     │   (container)    │
│ - vitest test   │     └─────────────────┘
│ - produce JUnit │
└─────────────────┘
          │
          ▼
┌─────────────────────┐
│ Upload test-results │
│ artifact (Vitest +  │
│ Busted XML)         │
└─────────┬───────────┘
          │
          ▼
 ┌─────────────────────┐
 │  Test Report        │
 │ workflow            │
 │ (.github/workflows/ │
 │ test-report.yml)    │
 └─────────┬───────────┘
           │
   ┌───────┴────────┐
   ▼                ▼
┌───────────────┐  ┌───────────────┐
│ Publish Vitest│  │ Publish Busted│
│ CheckRun      │  │ CheckRun      │
│ in GitHub UI  │  │ in GitHub UI  │
└───────────────┘  └───────────────┘
```

**Description:**

1. **Trigger:** a push or pull request on `main`.
2. **CI workflow:**

   * Node.js/TypeScript: checkout, caching, dependencies, lint, Vitest tests, build.
   * Lua: optional Busted tests in a Podman/Docker container.
   * Artefacts: the test XML files + the built client files.
3. **Test-report workflow:**

   * Runs on the default branch after CI has finished.
   * Downloads the artefacts.
   * Creates CheckRuns for Vitest and Busted.
4. **The benefit of the split:** PRs from forks can still be tested even though they have no permission to create CheckRuns directly.
5. **Containerisation:** guarantees a consistent Linux environment for Lua/Busted, independently of the self-hosted runner's OS.

## Tabular view

### CI workflow

Here is a clear table describing every step of the CI workflow, including platform, input/output and purpose:

```
| Job/Step                          | Platform       | Input/Resources                         | Output/Artifacts                      | Purpose/description                                                              |
|----------------------------------|----------------|----------------------------------------|---------------------------------------|-----------------------------------------------------------------------------------|
| Checkout repository               | cross-platform | GitHub repo                             | working directory with the code       | Clones the repository so that the following steps can access the source.          |
| Cache node modules                | cross-platform | package-lock.json                        | ~/.npm cached modules                  | Faster builds by reusing already installed Node modules.                          |
| Install dependencies (npm ci)     | cross-platform | package.json / package-lock.json         | node_modules                            | Installs exactly the project's dependencies.                                      |
| Lint (TypeScript / JS)            | cross-platform | source code (JS/TS)                      | lint report / errors                   | Checks TypeScript and JavaScript code for style and syntax errors.                |
| Ensure Vitest report dir exists   | cross-platform | -                                        | the TESTS/node/ directory              | Creates the directory for the JUnit XML results.                                  |
| Run Vitest and output JUnit XML   | cross-platform | Node tests                               | TESTS/node/vitest.xml                  | Runs the unit tests and outputs JUnit XML for test reporting.                      |
| Ensure Busted output dir exists   | Windows / cross-platform | -                                | the TESTS/lua/output/ directory        | Creates the directory for the Lua/Busted test results.                            |
| Ensure Podman machine is running  | Windows        | Podman installed                         | a running Podman machine               | Provides a Linux VM for the containerised tests.                                  |
| Run Lua tests (Busted) via container | cross-platform | Lua tests, container runtime           | TESTS/lua/output/busted.xml            | Runs the Lua unit tests inside a consistent Linux environment via a container.     |
| Upload test-results artifact      | cross-platform | TESTS/node/vitest.xml, TESTS/lua/output/busted.xml | GitHub artifact             | The test results are stored as an artefact and made available for reporting.       |
| Build client                       | cross-platform | source code                             | dist/                                  | Produces the built client code for deployment or further use.                     |
| Upload Node build artifacts        | cross-platform | dist/                                    | GitHub artifact                        | Makes the built client code available as an artefact.                             |
```

**Context and connections:**

* **Self-hosted runner:** everything runs locally or on your own machine, so Node, Lua and the tools can be installed beforehand. That speeds up CI runs.
* **Containerisation:** the Lua/Busted tests run in an Ubuntu environment, which ensures OS independence.
* **Artefacts:** both the Node tests and the Lua tests are exported as JUnit XML and uploaded, so that the second workflow (`test-report.yml`) can create CheckRuns.
* **Test-report workflow:** runs only on the default branch, consumes the artefacts and creates reports in the GitHub UI. This split allows fork PRs without write access to CheckRuns.

### Test-report workflow

```
| Job/Step                       | Platform       | Input/Resources                         | Output/Artifacts / GitHub UI       | Purpose/description                                                              |
|--------------------------------|----------------|----------------------------------------|-----------------------------------|-----------------------------------------------------------------------------------|
| Download test-results artifact  | cross-platform | the GitHub artefact "test-results"      | ./test-results/                     | Downloads the artefacts produced by the CI workflow (Vitest + Busted).            |
| List downloaded files (diagnose)| cross-platform | ./test-results/                          | console output                      | Checks whether the artefacts were downloaded correctly.                           |
| Publish Vitest JUnit report     | cross-platform | TESTS/node/vitest.xml from the artefact | GitHub CheckRun / PR UI            | Creates a CheckRun in the GitHub UI with the Vitest results (Java JUnit format).  |
| Publish Busted JUnit report     | cross-platform | TESTS/lua/output/busted.xml from the artefact | GitHub CheckRun / PR UI      | Creates a CheckRun in the GitHub UI with the Busted results (Java JUnit format).  |
```

**Context and connections:**

* This workflow runs **only on the default branch**, after the CI workflow (`ci.yml`) has finished successfully.
* It uses `workflow_run` to guarantee the dependency: test reports are generated only after the CI artefacts are available.
* **Artefact-based:** PRs from forks can run CI even without write access for CheckRuns. Only the default branch can publish the reports in the GitHub UI.
* **Test reporting:** `dorny/test-reporter@v2` turns the JUnit XML files into CheckRuns, including a summary, error messages and annotations in pull requests.
* **Configuration:** `fail-on-empty: false` makes sure that missing test files do not abort the report job. `only-summary` and `max-annotations` control how detailed the report is displayed.

The complete CI chain is therefore split into:

1. **The CI workflow** → runs the tests, creates the artefacts.
2. **The test-report workflow** → processes the artefacts, creates the GitHub UI reports.

This allows clean handling of fork PRs and consistent reporting independently of the runner's OS.

## Header, CI 1

```yaml
name: CI
on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]
```

* `name: CI` – the workflow's name.
* `on:` – the trigger conditions: run on pushes or pull requests on `main`.
* This lets both direct changes and PRs trigger the pipeline.

## Jobs

### build-and-test

```yaml
jobs:
  build-and-test:
    name: Build & Test
    runs-on: [self-hosted]
```

* `runs-on: [self-hosted]` – use of a self-hosted runner. Advantages: Node.js, Lua, Podman and the cache are already installed → faster runs.
* Job name: "Build & Test".

---

### Execution steps

#### Check out the repository

```yaml
- name: Checkout repository
  uses: actions/checkout@v4
```

* Fetches the source code from GitHub into the runner workspace.
* Indispensable, since every further step needs the code.

#### Node module cache

```yaml
- name: Cache node modules
  uses: actions/cache@v4
  with:
    path: ~/.npm
    key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
    restore-keys: |
      ${{ runner.os }}-node-
```

* Prevents a repeated `npm ci` when the dependencies are unchanged.
* The key is based on the OS + a hash of `package-lock.json`.

#### Install Node dependencies

```yaml
- name: Install dependencies
  run: npm ci
```

* A clean installation of the Node.js packages.

#### Linting

```yaml
- name: Lint (TypeScript / JS)
  run: npm run lint
```

* A static code check for TypeScript/JS.

#### Prepare the Vitest report folder

```yaml
- name: Ensure vitest report dir exists
  run: mkdir -p TESTS/node
```

* Makes sure the directory for the JUnit output exists.

#### Run Vitest

```yaml
- name: Run Vitest and output JUnit XML
  run: npm test -- --reporter=junit --outputFile=TESTS/node/vitest.xml
```

* Runs the Node tests and produces JUnit XML (`vitest.xml`) for later use in the test-report workflow.

#### Prepare the Lua test folder

```yaml
- name: Ensure busted output dir exists
  shell: pwsh
  run: |
    New-Item -ItemType Directory -Path TESTS/lua/output -Force | Out-Null
```

* A PowerShell command for the Windows runner; creates the directory for the Busted JUnit XML.

#### Start the Podman machine

```yaml
- name: Ensure Podman machine is running
  shell: pwsh
  run: |
    $machineStatus = podman machine list --format json | ConvertFrom-Json
    if ($machineStatus.Count -eq 0) { podman machine init }
    podman machine start
```

* Checks whether the Podman VM is running.
* Initialises and starts it if needed.
* Important for the Windows runner, since Podman only runs containers through a Linux VM.

#### Lua tests via a container

```yaml
- name: Run Lua tests (Busted) via container
  shell: pwsh
  run: |
    $tool = if (Get-Command podman -ErrorAction SilentlyContinue) { "podman" } elseif (Get-Command docker -ErrorAction SilentlyContinue) { "docker" } else { "" }
    if ($tool -eq "") {
      Write-Host "Neither Podman nor Docker found on runner. Attempting native Linux installation if applicable."
      if ($env:RUNNER_OS -eq "Linux") {
        sudo apt-get update
        sudo apt-get install -y lua5.3 liblua5.3-dev luarocks build-essential
        luarocks install --local busted
      } else {
        Write-Host "Busted not available on this platform. Skipping Lua tests."
        exit 0
      }
    }
    if ($tool -ne "") {
      Write-Host "Using container runtime: $tool"
      & $tool run --rm -v "${{ github.workspace }}:/work" -w /work ubuntu:22.04 bash -lc `
        "apt-get update -qq && apt-get install -y -qq lua5.3 liblua5.3-dev luarocks build-essential && luarocks install --local busted && busted --pattern='*.spec.lua' --lpath='./?.lua' --output-junit=/work/tests/lua/output/busted.xml TESTS/lua || true"
    }
```

* Checks whether Podman or Docker is installed.
* If one is present, Busted runs in a short-lived Ubuntu container → a consistent Linux environment for the tests.
* If no container runtime is available, a native installation is used on Linux runners.
* Goal: platform-independent execution of the Lua tests and production of `busted.xml`.

#### Upload the test results

```yaml
- name: Upload test-results artifact
  uses: actions/upload-artifact@v4
  if: always()
  with:
    name: test-results
    path: |
      TESTS/node/vitest.xml
      TESTS/lua/output/busted.xml
```

* The generated JUnit XML files are uploaded as an artefact.
* Used later in the separate workflow to display test reports in the GitHub UI.

#### Node build

```yaml
- name: Build client
  run: npm run build
```

* Builds the client project.
* Separate from the test process, but can run in parallel with it or afterwards.

#### Upload the Node build artefacts

```yaml
- name: Upload Node build artifacts
  uses: actions/upload-artifact@v4
  with:
    name: node-build
    path: dist/
```

* Enables, for example, downloading for deployment or a release.

# `.github/workflows/test-report.yml` – second-stage CI

**Purpose:**
This pipeline runs only on the default branch, after the first CI workflow (`CI`) has finished.

* Downloads the test results as an artefact
* Creates GitHub CheckRuns for the PR UI

---

### Header

```yaml
name: Test Report
on:
  workflow_run:
    workflows: ['CI']
    types:
      - completed
```

* `workflow_run` – triggers as soon as the `CI` workflow has finished.
* Advantage: separate logic for PRs from forks, which otherwise cannot create CheckRuns because of token restrictions.

```yaml
permissions:
  contents: read
  actions: read
  checks: write
```

* The GitHub permissions needed to create CheckRuns.

---

### Job: publish-report

```yaml
jobs:
  publish-report:
    name: Publish Test Report
    runs-on: ubuntu-latest
```

* Runs on hosted Ubuntu. No self-hosted dependencies necessary.

---

### Steps

#### Download the artefact

```yaml
- name: Download test-results artifact
  uses: actions/download-artifact@v4
  with:
    name: test-results
    path: ./test-results
```

* Fetches the XML files from the CI workflow.

#### Diagnose the artefacts

```yaml
- name: List downloaded files (diagnose)
  run: |
    ls -R test-results || true
```

* Checks whether the XML files arrived correctly.

#### Publish the Vitest report

```yaml
- name: Publish Vitest JUnit report
  uses: dorny/test-reporter@v2
  if: always()
  with:
    artifact: test-results
    name: Vitest
    path: 'TESTS/node/vitest.xml'
    reporter: java-junit
    fail-on-empty: false
    only-summary: 'false'
    max-annotations: '10'
```

* Creates CheckRuns for the Node tests in the GitHub UI.
* The `java-junit` reporter supports the XML format Vitest produces.

#### Publish the Busted report

```yaml
- name: Publish Busted JUnit report
  uses: dorny/test-reporter@v2
  if: always()
  with:
    artifact: test-results
    name: Busted
    path: 'TESTS/lua/output/busted.xml'
    reporter: java-junit
    fail-on-empty: false
    only-summary: 'true'
    max-annotations: '5'
```

* The same for Lua/Busted.
* `only-summary: true` – individual test cases are not turned into annotations, only the summary.

---

**Connections and architecture:**

1. **`ci.yml`** – runs the tests and the build and produces the artefacts, without CheckRuns → PRs from forks can still be tested successfully.
2. **`test-report.yml`** – runs on the default branch and creates CheckRuns from the uploaded artefacts.
3. **A self-hosted runner** → faster, with all dependencies preinstalled.
4. **A container for Busted** → platform-independent, a consistent Linux environment for the Lua tests.
5. **Artefacts** → the separation of test execution and reporting prevents problems with PRs from forks.
